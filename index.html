About this website: what you are looking at

This page follows one simulated cooking learner across 40 practice sessions. Two cooking-coaching methods choose each session’s practice. The Model internals section shows session arithmetic on the left and a matching animated demonstration on the right.

Purpose: both cooking-coaching methods make automation of cooking procedures learnable through models and sequences of practice. Each session changes the learner, so the next best assignment depends on that history.
Cooking coaching: choosing practice across many sessions for knife, heat, and timing skills.
Model: the program’s current picture of the learner, including estimated skills and learning speed.
Learning: revising that picture after each noisy observation.
Readiness: whether prerequisite skills are high enough for a compound recipe to work at full strength.
Plan ahead: comparing predicted results for the next two sessions before assigning the current session.
Hidden skills: true skill values used by the simulation; coaches receive noisy observations derived from them.

The task

Assign the next useful practice task. The learner has hidden knife, heat, and timing skills. Each assignment changes those skills, and the next assignment inherits the result. The 40 sessions form one connected coaching sequence.

The learner

True skills stay in [0,1]. Isolated drills practice one skill separately from preparing a complete dish. Compound recipes improve several skills when prerequisites are met. Improvement shrinks as a skill approaches 1. From [0.65,0.15,0.35], the maximum cumulative gain is 1.85.

The scores

Coaches receive noisy skill readings and one score jump: observed new-skill total minus previous true-skill total. Noise can make a weak action look strong for one session. Cumulative gain adds true improvement across all three skills.

The sessions

Session 1–20 establishes the crossover. After session 20, a new stove cuts heat skill to 65% and lowers its learning rate. A coach that revises its model adapts; a coach that keeps old averages lags.

Training setup

A simulated cooking learner begins with knife 0.65, heat 0.15, timing 0.35. Each coach receives noisy observations rather than those true values. Each session assigns one practice task; the learner improves with diminishing returns:

s′ = s + α* · w · exp(−6 · prerequisite shortfall) · (1 − s)  ·  observation = true skill + N(0, σ²)

Isolated drills

knife_drill, heat_drill, and timing_drill practice one skill separately from preparing a complete dish. They carry no prerequisites and give safe, narrow gains.

Compound recipes

easy_recipe needs 0.2 everywhere. stretch_recipe needs knife 0.5, heat 0.45, and timing 0.4. When heat is weak, the gate reduces a stretch recipe toward small gains.

New stove

After session 20, the learner’s heat skill becomes 65% of its prior value and the heat learning rate changes from 0.14 to 0.055. A revisable model tracks that change; fixed averages adjust more slowly.

How Bandit A decides: UCB

UCB means Upper Confidence Bound. Here it names the selection rule that combines remembered performance with a bonus for less-tried actions. It has no connection to UC Berkeley in this page.

UCB(action) = remembered average(action) + 0.06 × √(ln(current round + 1) / plays(action))

Remembered average: mean of past session score jumps for that action.
Plays: number of sessions in which that action was assigned.
Current round: session count including the choice being made.
Bonus: larger for actions assigned fewer times; it encourages checking alternatives.

Conclusion: what the comparison shows

The comparison has three parts. First, World-Model B starts with an incomplete readiness estimate, so early stretch recipes yield little. Next, stove drift tests adaptation after session 20. Finally, fixed plans isolate the gate effect across ten sessions. The sections below follow that order: early and late behavior, drift and noise, and gate comparison.

Why B starts behind, then moves ahead

1 · B starts with an incomplete readiness estimate

Its gate estimate gate_hat starts at 0, so its planner assigns stretch_recipe. With true gate strength 6 and heat at 0.15, those early assignments yield small gains. Each shortfall raises the gate estimate toward the true gate. Bandit A measures scores directly and shifts toward heat_drill and easy_recipe sooner:

Orange tracks the learned gate; blue tracks the estimated heat learning rate; dotted lines mark true values. Early mismatch explains the early gap.

2 · Then sequencing beats averaging

After gate_hat ≈ 5–6 and settled learning-rate estimates, B assigns heat drills until heat crosses 0.45, then assigns the stretch recipe at full gate strength. It also moves away from saturated skills. A continues to favor actions with strong early averages while their returns decay. That difference widens the gap after the crossover.

Try the dials — break the result on purpose

Set gate strength to 0: prerequisites vanish and the stretch recipe becomes strongest from the start. Set noise σ to 0.18: every coach reads the learner less accurately. Set drift Off: B still wins late, and the post-session-20 adaptation comparison disappears. The crossover comes from the setup.

At session 20 the true conditions change for both coaches. B detects forecast errors, raises uncertainty, and relearns a slower heat rate. function envStep(env, a, o) {           // TrueLearnerEnv.step
  const g = gate(env.s, a, o.gateK);     // exp(-gateK * shortfall)
  for (let k = 0; k < 3; k++)
    env.s[k] = clip(env.s[k] + env.alpha[k]*a.w[k]*g*(1-env.s[k]), 0, 1);
  const obs = env.s.map(v => clip(v + gauss(env.rng)*o.noise, 0, 1));
  return { obs, score: sum(obs) - sum(env.prev) };
}

// Coach B update: Kalman belief + learn alpha + learn the gate itself
if (compound && predictedGain > 0.03) {
  const miss = clip(1 - realisedGain / predictedGain, 0, 1);
  B.gateHat = clip(B.gateHat + 1.2 * miss, 0, 8);   // 0 = "no prerequisites"
}

Build on it: brighter, clearer, more visible

What judges (and users) should feel in the next iteration — functionality first, then shine:

1 · Make the invisible visible

A live “learner brain” panel next to every chat: belief bars, uncertainty, and the planner’s next-two-moves — exactly like the inspector above, but inside the product. The world model stops being a claim and becomes something you watch thinking.

2 · Let users drive

“You be the coach” mode: at each session the user picks the action, then the page reveals what A would have done, what B planned, and what the truth did. Feeling the gate once beats reading about it three times.

3 · Real voices via Muse Spark

Wire MODEL_API_KEY so learner text is extracted and coach replies are written by Muse Spark through the Meta Model API, with the offline extractor as the demo-safe fallback. Same decisions, human conversation.

4 · More learners, honest edges

Archetype sampling (varied starting skills, learning rates, noise) so claims about slow learners receive direct tests, with loss cases displayed.

5 · Presentation polish

Animated session replay for the demo video (this page’s Play button is the storyboard), a one-screen verdict header, and exportable charts. Bright where it earns attention — the crossover moment — quiet everywhere else.
